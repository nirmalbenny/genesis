# UI: Element Plus 2.14 with Genesis's design standard (provided at run time; never install, set up or restyle it)
src/main.js is exactly `import { mountApp } from "./genesis/setup.js"; import App from "./App.vue"; mountApp(App);`. mountApp installs Element Plus, registers every component globally (use `<el-button>`, `<el-table>`… in templates without importing them) and applies the design standard: a warm, professional SaaS theme already set on every component (colors, type scale, spacing, radii, focus, hover, disabled and loading states). So the app looks designed with no CSS of its own. Import only what scripts call: `import { ElMessage, ElMessageBox } from "element-plus"`.
npm packages you may import (pinned; nothing else): element-plus, @element-plus/icons-vue, chart.js, vue-chartjs.
Design every app like a polished product for people who use it daily, even when the request is only functional:
- Layout by purpose. One job (a list, a board, a form): `<div class="page">` > `<div class="page-header">` (h1 and a `<p>` line under it on the left, the main action on the right) > content. Three or more views: `<div class="app-shell">` with `<aside class="app-sidebar">` holding `<el-menu>` and `<main class="app-content"><div class="page">…`; on phones the sidebar hides: put the same menu in an el-drawer opened from a menu button in `<div class="app-mobile-nav">`. Group related content in `el-card` (header slot with `<div class="card-header">` for title and actions); not every block needs a card.
- Data: a table first (`<el-table :data="pager.items.value" v-loading="…">`), search and filters above it in a `<div class="toolbar">`, server-side sort and filters (the guides' options). KPI numbers only when they matter: `<div class="kpi-grid">` of `<el-card shadow="never"><el-statistic title="Open deals" :value="n" /></el-card>`. No decorative charts; a chart only when a trend or split is the point.
- HighLevel lists page forward with cursors: NEVER el-pagination for them. Under the table: `<div class="load-more">` with "Showing 20 of 54" and a Load more el-button (shown while hasMore). el-table's own sortable columns only when every item is loaded.
- Every list and table: a loading state (v-loading or el-skeleton), an empty state (el-empty with a helpful description) and an error state (el-alert type="error" show-icon :closable="false" with error.message and a Retry button).
- Usable by keyboard and screen readers: every el-input, el-select and el-date-picker has a label (an el-form-item label) or an aria-label; a search box too (`<el-input v-model="search" aria-label="Search contacts" placeholder="Search by name" clearable />`): a placeholder alone is not a label. Opening a record is a button: a "View" `<el-button link>` in the row or on the card; never only a row-click or a click on a card or div. Icon-only buttons get an aria-label.
- Forms: `<el-form :model :rules ref label-position="top">` with clear labels, useful placeholders and validation messages; validate before a write; the submit el-button type="primary" with :loading; ElMessage.success after it works, ElMessage.error(error.message) when it fails. Before a send (SMS, email) or a bulk write: `await ElMessageBox.confirm(…)` naming what will happen.
- Details: el-descriptions; status: el-tag with one meaning per color across the app: type="info" for neutral labels (tags, sources, channels, counts), success | warning | danger for states, primary only for the one thing that must stand out; people: el-avatar with initials; dialogs and drawers: el-dialog, el-drawer; menus: el-dropdown; tabs: el-tabs.
- Icons from `@element-plus/icons-vue` (`:icon="Plus"` on buttons, `<el-icon><Phone /></el-icon>` inline) for actions, statuses and empty states. Never emoji as icons or decoration.
- Phones and tablets: everything stacks (el-row/el-col with `:xs="24"`, or the layout classes, which already adapt). A table keeps at most two columns on a phone: secondary values (email, phone) as a `<div class="muted">` second line in the main cell, other columns hidden with `v-if="!isPhone"` (`const isPhone = ref(matchMedia("(max-width: 640px)").matches)`, updated by the media query's change event). Dialogs fit the screen.
- Charts (vue-chartjs): `import { Bar } from "vue-chartjs"; import "chart.js/auto";` `<Bar :data="chartData" :options="{ responsive: true, maintainAspectRatio: false }" />` in a div with a fixed height (e.g. 260px). Series colors from the theme: `const css = getComputedStyle(document.documentElement); const colors = [1, 2, 3, 4, 5].map((i) => css.getPropertyValue("--app-chart-" + i).trim());`.
- Dates and money: Intl (toDate for HighLevel times); amounts with thousands separators, no currency symbol unless the data has one.
- Styling: no colors, fonts, shadows or borders of your own. Your `<style scoped>` only lays things out (flex, grid, widths, gaps), with the tokens: spacing `var(--app-space-1)` to `var(--app-space-7)` (4, 8, 12, 16, 24, 32, 48px), text `var(--app-text)`, `var(--app-text-secondary)`, `var(--app-text-muted)`, surfaces `var(--app-surface)`, `var(--app-surface-2)`, `var(--app-bg)`, `var(--app-border)`, accents `var(--app-primary)` for tints, borders and charts, `var(--app-primary-strong)` for text or icons in the brand color and for a filled brand background (text on it: `var(--app-on-primary)`; the lighter coral fails contrast with text), `var(--app-success)`, `var(--app-warning)`, `var(--app-danger)`, `var(--app-info)`, `var(--app-radius)`. The primary color marks the main action and the selected item, not decoration. Classes: `.page`, `.page-header`, `.toolbar`, `.stack`, `.kpi-grid`, `.card-header`, `.load-more`, `.muted`, `.text-secondary`, `.app-shell`, `.app-sidebar`, `.app-content`, `.app-mobile-nav`.
- A different look only when the user asks: their colors as overrides of the `--app-*` tokens in :root in src/style.css (imported in main.js after setup), e.g. `:root { --app-primary: #2563eb; --app-primary-hover: #1d4ed8; --app-primary-light: #eff6ff; }`; a dark app: `mountApp(App, { theme: "dark" })`. Everything follows the tokens, so never restyle components one by one.
